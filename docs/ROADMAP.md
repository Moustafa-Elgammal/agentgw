# Roadmap

Each milestone ends with something demonstrable. Dates are not set: this is a solo,
spare-time project.

| Milestone | Deliverables | Exit criterion | Status |
|---|---|---|---|
| M0 Foundations | Repo, CI, core types, manifest validator, policy (in memory), signing, REST connector, audit, pipeline, dev API | End-to-end call through a signed backend with caps, cooldown and audit | Done |
| M1 MCP transport | Official Go SDK, runtime tool registration from the manifest, streamable HTTP, YAML manifest, conformance suite v0 | An MCP client lists and calls tools through the gateway | Done |
| M2 Policy engine | Redis-backed Policy, concurrency tests, confirmations in Postgres, kill switches (switches, policy contract suite, Redis store, confirmations in memory and Postgres, dev admin endpoints) | Concurrent reserves never exceed a cap; Redis-down behavior matches the spec | Done |
| M3 Auth | Protected resource metadata, token validation, authorization server with link tickets and consent, grants and revocation | A scripted PKCE client completes the flow; wrong-audience and revoked tokens are rejected | Done. OIDC login at consent is built with `go-oidc` as the signature verifier, wired to `--oidc-*` flags and the Helm chart, and tested end to end against a fake provider and against Dex (tutorial 8) with real keys ([design](design/oidc-consent.md)). Not yet run against a real provider such as Dex or Keycloak |
| M4 Studio and player APIs | Manifest upload and rollback, key rotation, grant list and revoke, activity feed | A studio onboards with a manifest and no backend code | Done. Manifest upload and rollback, key rotation, grant list and revoke, and the activity feed (player and admin) |
| M5 Relay | WebSocket hub, multi-replica routing, wire protocol for a Unity package | A sample game is played by an agent through the relay | Built: relay hub, tickets, Redis routing, `backend: relay`, a sample client. Wire protocol v1.1 is hardened and tested (limits in hello, deadlines, in-flight cap, retry hints, garbage and flood handling, slow clients, bye). Not done: running the C# client inside Unity |
| M6 Hardening | Load and soak tests, SSRF and injection tests, dashboards, runbooks, Helm chart | Pilot-ready in Coach mode, then Operator mode behind a flag | Built: metrics and ops listener (`internal/obs`), SSRF-safe connector and injection tests, Helm chart, Grafana dashboard, alerts, runbook, load tool. Not done: a long soak run (the kill switch API and Operator flag moved to M10) |
| M7 Open source release | Pre-flight audit (independence, secrets, history, licenses), repository settings and protections, security and DCO automation, release pipeline (binaries, signed multi-arch images, SBOM, changelog), a README for strangers, decision on publishing `tinycity-mock` | The repository is public, `v0.1.0` is tagged and verifiable, and a stranger runs the demo in five minutes | Built and published: the repository is public and CI, vulnerability scan and CodeQL run on every push. Audit (`docs/AUDIT-REPORT.md`), workflows, GoReleaser, signed images, SBOM, release and settings guides, README, `tinycity-mock` community files. Left to do: confirm `docs/REPO-SETTINGS.md` is applied, tag `v0.1.0` (no tag or release exists yet) |
| M8 Project site and docs on GitHub Pages | Static site built from `docs/` in a container, landing page that shows the features, concepts and operate pages, generated reference (manifest, flags, errors, OpenAPI for the studio API), Pages deploy workflow, link and snippet checks | The site is live at the project's Pages URL and rebuilds on every merge | Live at <https://elgx.me/agentgw/> and rebuilt by `pages.yml`: Starlight site in `site/`, landing page, generated reference and OpenAPI with drift tests, link and manifest-snippet checks. Left to do: record the terminal demo |
| M9 Developer guides | Seven getting-started tutorials, best practices, runnable examples in Go and Python, cookbook, troubleshooting by error code, guides verified by CI | A developer onboards a toy game by following the guides alone | Built: seven tutorials with CI-run scripts (verified together), best practices, cookbook, troubleshooting by code, FAQ, signing examples in Go, Python, TypeScript and C#, two pet-shop backends, `guides.yml`, site section. Not done: a ten-minute read-through by someone who has never seen the project |
| M10 Pilot readiness | Studio-signed kill switch API, `--max-scope` coach cap for first pilots, request body limits and server timeouts, soak run | A pilot runs in Coach mode with a kill switch the studio can reach, then Operator mode by raising one flag | Built: signed kill switches (`internal/switchapi`), `--max-scope`, `--max-body` (`internal/bodylimit`). Not done: the first real release (M11). The wire protocol hardening (M5), the 1 hour soak run and OIDC login at consent (M3) are done |

Left: settings, the first real release, stranger walk-through |

## M1 first task

Pin the official `github.com/modelcontextprotocol/go-sdk` version and prove two things in a
spike: registering tools from a runtime schema (not Go structs), and serving a different
tool set per request. Everything else in M1 builds on those two.
